# Recall: dated memory, fresh evidence

The hard part is answering “has it changed since we spoke?” A model's recollection is not a reliable baseline, and today's price does not establish when a price changed. Recall keeps those two kinds of evidence separate.

**How it works.** Next.js serves a small React interface and a streaming Node route. Supabase PostgreSQL stores question timestamps, timezone, original answers, and search excerpts with URLs and retrieval times. An opaque, signed, HttpOnly cookie identifies a browser workspace. Every server database operation scopes records to that owner; composite foreign keys prevent attaching turns to another owner's conversation. RLS denies browser access. Supabase credentials never reach the client. This is an evaluation identity, not a replacement for production login.

A bounded LangGraph runs **planning → research → responding**. The application retrieves eight recent turns plus up to sixteen historical matches across conversations. Chrono and Luxon resolve dates in the user's IANA timezone into UTC day boundaries; PostgreSQL full-text search supplies topic matches. A Groq model produces a validated plan: topic keywords, queries, or a clarification. If its topic query recovers additional history, one extra planning call incorporates the actual vendors and baseline before research. There is exactly one external agent tool: `web_search`, backed by Tavily. Memory is application-managed context, not an LLM-callable tool.

**Speed and correctness.** Ordinary recall skips web search. Most research needs one to three queries; a five-vendor price/change comparison can use ten. Queries run at concurrency four, with deadlines and a total turn budget. Excerpts are deduplicated and distributed across queries within a context budget. Groq streams the answer as generation starts. There is no web-result cache for “has it changed?” questions. Prompts require first-party evidence, dated announcements for changes, consistent billing units, and separate verified, changed, and unverified claims. Retrieval time is never presented as publication time. Search failures remain explicit in answer context. Citation IDs link only to supplied sources; this prevents invented citation links, but cannot prove a passage supports a claim. Search excerpts are untrusted and incomplete; prompt injection and grounding remain evaluation risks.

**Durability.** The database records a question before inference. A transaction and per-conversation lock admit one pending turn; request IDs make completed retries replayable without repeating paid work. Disconnects cancel provider calls and mark partial responses as failed. Only completed answers become baselines; failed questions remain recallable. Abandoned pending turns expire on the next admission. Sources and final answers are saved before completion. Storage outlives graph execution; checkpoints are unnecessary for this short, bounded request.

Groq's low-TPM tier needs explicit limits: planning reserves 700 output tokens, answers 1,400, with low reasoning effort and a 14,500-character serialized context budget. Stored evidence remains complete. Provider cooldowns get at most two retries of up to 30 seconds each, with visible status and cancellation; exhausted limits are described as usage limits, not bad keys. This is not a distributed quota scheduler, and character budgets approximate token counts.

**Choices and rejected options.** Next.js keeps UI and server contracts together; LangGraph makes limits visible; Supabase supplies durable, indexed memory; Groq is the requested low-latency provider. The configurable default `openai/gpt-oss-120b`, hosted on Groq, is a starting point, not a state-of-the-art claim. I rejected an unconstrained agent loop (unpredictable latency), summary-only memory (lost dates and prices), a vector database first (extra dependency and weaker exact-date guarantees), and a verifier call on every answer (latency without guaranteed factuality). Text search can miss synonyms; date parsing is English-first. Long conversations can exceed recall/context budgets; truncation metadata tells the model when excerpts are incomplete.
